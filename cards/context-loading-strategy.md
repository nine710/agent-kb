## Options

### Option A: 常驻静态前缀

把关键信息放进静态前缀（系统提示词 + 工具定义），在每次推理时拼在轨迹之前、整个对话保持不变。静态前缀的不变性使 KV Cache / Prompt Cache 持续命中——前缀一旦确定就应当保持字节级稳定。适合稳定、全场景适用的信息（身份、核心规则、常用工具定义）。

### Option B: 按需加载（渐进式披露）

不把所有信息一次性塞入上下文，而是按需加载：Agent Skills 只常驻元数据（`name` + `description`），完整内容被选中后通过专用工具加载为 tool result；工具定义本身也可延迟加载（deferred loading / tool_search），会话启动时只注入名称与简述，完整 schema 待模型搜索后才追加到上下文末尾。静态前缀保持不变，故仍缓存友好（因果注意力决定了末尾追加不破坏已缓存的前缀）。

### Option C: 运行时压缩

允许上下文随交互积累，在两次 API 调用之间由 Agent 框架对历史中的 tool results 做压缩 / 摘要替换。有两个动机：① 控制长度与成本（窗口有限、token 越多越贵越慢）；② 提升思考质量——把"需要思考才能得到的结论"换成"可直接检索的高密度知识"（上下文学习的内部机制更像检索而非推理）。System Prompt 与工具定义永不压缩；只压缩轨迹中的工具输出，且最好在接近阈值时批量压缩，而非每轮都压。

### Option D: 外部化（不进主上下文）

让大体积信息根本不进入主上下文，只取回结论或片段：① **子 Agent 上下文隔离**——把"读取大量文件 / 在代码库大范围搜索"这类会产生海量中间内容的任务委派给独立子 Agent，只回传几百 token 的结论摘要（"隔离优于压缩"）；② **RAG / 知识库**——把跨会话的持久知识放在外部存储，按需检索相关片段注入，而非常驻。主上下文预算与 KV Cache 前缀都不受 bulk 影响。

## Tradeoffs

| | 优势 | 代价 |
|---|---|---|
| A 常驻 | 命中缓存、延迟与成本最低；全场景一致；指令遵循最强 | 前缀须字节稳定，任何改动（时间戳 / 动态配置 / 工具重排）都击穿整条前缀缓存；膨胀→注意力稀释、上下文腐化（装得下但找不到） |
| B 按需 | 前缀稳定→缓存友好；上下文只装载相关内容；能力可模块化、版本化、分享 | 依赖路由准确度（Skill `description` 要"Use when"+反例）；指令落在上下文中间→instruction-following 模型间差异大；多一次工具加载往返 |
| C 压缩 | 控制长度同时提升信息密度；显式总结可审查、可跨会话复用；上下文感知压缩可省 ≥75% token | 有损、需额外 LLM 调用；替换点之后缓存失效；最易丢失早期架构决策、约束理由、失败路径；hash / UUID / URL 改一位即失效 |
| D 外部化 | bulk 不进主上下文，前缀与预算都不受影响；可承载远超窗口的知识；跨会话持久 | 子 Agent 看不到主上下文，任务须自包含；RAG 受检索精度 / 知识时效 / 信息冲突制约；检索质量即能力上限；多一跳检索延迟 |

## Apply to Agent Development

- **先判信息性质，再选承载形态**：稳定且全场景适用→A 常驻；按场景 / 领域且会膨胀→B 按需；随交互积累且量大→C 压缩或 D 外部化。
- **守住静态前缀的"字节稳定"**：时间、余额、计数等动态值绝不进 system prompt，应放上下文末尾（Agent 状态栏）或按需用工具获取，否则每轮击穿缓存。
- **优先"隔离 / 外部化"于"事后压缩"**：能让 bulk 不进主上下文（子 Agent / RAG）就别让它进了再压；压缩是有损补救，隔离是釜底抽薪。
- **压缩按信息生命周期分层**：噪声直接删（不对噪声做摘要）、工具结果可删只留 pass/fail 结论、架构决策与约束理由与失败路径不得摘要；标识符原样保留。
- **别等窗口满了才动**：上下文腐化（装得下但找不到）比溢出更隐蔽；信息密度不对时就该压缩 / 外部化，而非等到 token 撑满。
- **显式提炼优于被动检索**：与其让模型在海量原始记录里现算（如逐个数黑猫），不如主动把结论算好放进上下文（状态栏）或换入压缩摘要。
- **按需加载要对齐模型厂商训练方法论**：Skills / 中间位置指令遵循在对应生态内表现最优，且需要较新模型支持。

## Anti-Patterns

- 把偶尔才用的知识每次都常驻 → 注意力稀释、上下文腐化。
- 在 system prompt 注入动态值（时间戳 / 余额 / 计数）→ 每轮击穿 KV Cache 前缀。
- 逐轮压缩而非接近阈值批量压缩 → 频繁破坏缓存。
- 对噪声做摘要 → 浪费 token（噪声应直接删除）。
- 压缩时丢掉早期架构决策、约束理由、失败路径，或改错 hash / UUID / URL → 后续工具调用直接失效。
- 让主 Agent 亲自做会产生海量中间内容的探索（读十几个文件 / 大范围搜索）→ bulk 永久占据窗口，应委派子 Agent。
- 期望模型从冗长上下文自动归纳统计 → 注意力是检索不是推理，应主动算好结论再注入。
- RAG 知识库不治理时效与冲突 → 检索到过期 / 矛盾信息。
