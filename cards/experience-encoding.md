## Options

### Option A: 沉淀为知识

把经验整理为可检索的案例、事实、模式或知识条目，在相关任务到来时再取回使用。

### Option B: 写成指令

把稳定的经验写进 Prompt、Skill 或其他行为指令，让模型在推理时直接遵循新的步骤、偏好或约束。

### Option C: 写成程序

把经验形式化为 Harness 逻辑、工具校验、工作流、规则或自动化脚本，使它以确定性执行方式影响后续行为。

### Option D: 写入模型参数

通过训练或后训练把经验更新到模型参数，使能力不依赖显式检索或运行时指令加载。

## Tradeoffs

| | 优势 | 代价 |
|---|---|---|
| A 知识 | 可审计、可按需检索，更新和回滚局部 | 是否被取回取决于检索质量；知识与行动之间仍需推理 |
| B 指令 | 对行为步骤影响直接，部署快 | 指令膨胀会增加上下文和冲突风险；效果依赖模型遵循 |
| C 程序 | 对可形式化经验最可靠，可验证、可测试和可审计 | 开发维护成本高，难表达模糊策略；过度约束会限制自主性 |
| D 参数 | 可把能力内化，运行时不需要显式加载经验 | 训练成本、可解释性和回滚难度最高，验证不足时风险大 |

## Apply to Agent Development

- 经验是可检索事实、案例或诊断线索时优先 A。
- 经验是可语言化的步骤和偏好、但仍需要模型裁量时用 B。
- 经验可转化为确定性条件、校验或流程时用 C，尤其适合安全和重复性要求高的行为。
- 只有数据、环境、评估和回滚机制充分时才考虑 D；不要把运行时问题默认升级为训练问题。
- 每次沉淀前先完成问题定位和验证，发布后保留回滚通道；完成一次任务不等于能力真正提升。

## Anti-Patterns

- 把未经验证的单次成功轨迹直接写入长期知识或系统指令。
- 用冗长指令堆叠替代可形式化的程序校验。
- 为了追求自动进化直接更新参数，却没有隔离评估、发布和回滚。
- 把需要按任务检索的细节永久常驻，造成上下文膨胀和陈旧规则。
- 把“完成一次任务”误当作“系统能力已提升”，不测量泛化和副作用。
